# Change Order ID Format

## Goal
Change the generated order ID from the current `{month}{day}-{last5OfPhone}-{2random}` (e.g. `78-01455-31`) to a new format `{2random}-{last4OfPhone}-{2random}` (e.g. `87-5428-77`).

## Current State (verified)
Order ID is generated **once** per order attempt, in **two** client-side files, and passed through unchanged everywhere:
- `src/components/checkout/OrderDialog.jsx` (~line 237-239)
- `src/pages/order.js` (~line 171-173)

Both currently do:
```js
const nowBD = new Date();
const phoneDigits = (formData.phoneNumber || '').replace(/\D/g, '');
const uniqueId = `${nowBD.getMonth() + 1}${nowBD.getDate()}-${phoneDigits.slice(-5) || '00000'}-${Math.floor(10 + Math.random() * 90)}`;
```

`orderId` is used downstream only as an opaque string: unique DB index (`Order.js`), admin display/search (`admin/orders.js`, `admin/sms.js`, `admin/order-errors.js`), error/SMS logs, and the SMS body `#ORD${id}` (`lib/sms.js`). **No code parses the old structure**, so changing the format at the two generation sites is fully isolated.

## Decision
New format: `{2random}-{last4OfPhone}-{2random}`
- First 2 digits: random (10–99)
- Middle 4 digits: last 4 digits of the phone (fallback `0000`)
- Last 2 digits: random (10–99)

## Changes

### 1. `src/components/checkout/OrderDialog.jsx`
Replace the generation block (~lines 234-239). Remove the now-unused `nowBD` if nothing else uses it. Update the comment to describe the new format:
```js
// Format: {2random}-{last4OfPhone}-{2random}
// e.g. phone ...5428 -> "87-5428-77". The random digits keep the id
// unique if the same phone orders again the same day.
const phoneDigits = (formData.phoneNumber || '').replace(/\D/g, '');
const uniqueId = `${Math.floor(10 + Math.random() * 90)}-${phoneDigits.slice(-4) || '0000'}-${Math.floor(10 + Math.random() * 90)}`;
```
Verify `nowBD` is not referenced elsewhere in the file before removing it; if it is, leave it in place.

### 2. `src/pages/order.js`
Apply the identical change at ~lines 168-173 (update comment, remove `nowBD` if unused, new `uniqueId` formula).

## Validation
- `npx eslint src/pages/order.js src/components/checkout/OrderDialog.jsx` (project's `next lint` is broken by an ESLint 9 + eslint-config-next incompatibility — run eslint directly).
- Manual: place an order → confirm the confirmation screen, admin Orders list, SMS body `#ORD...`, and SMS admin log all show the new `XX-YYYY-XX` format (middle = last 4 of phone).
- Duplicate/retry behavior unchanged: orderId still unique per order; `409` still returns for a repeated id.
- No other file references the old format, so no further edits required.
